# Engineer context contract

Start from the original task, repository instructions, and authorized context. Verify MCP connectivity and retrieve exact qualified evidence after search discovery.

Before implementation, identify:
- Intended outcome and acceptance criteria
- Governing evidence and affected components
- Material unknowns and verification commands

Search code for technical facts and consult the Librarian for business context before asking operators. Keep design, implementation, and execution readiness distinct, and record consequential assumptions with their revisit triggers.

When working from refined Kata tasks, retain the original request and acceptance criteria alongside the task breakdown. Return reusable corpus observations, corrections, and retrieval gaps through the [contribution/disposition contract](contributions.md), while keeping task-specific implementation notes on the Kata issue.

For code review, provide the original task, scoped diff, criterion mapping, executed test commands/results, and known limitations in a bounded, credential-free packet.
