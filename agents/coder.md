# Coding-agent context contract

Use the original task, applicable repository instructions and authorized
context. Verify your own MCP connection and retrieve exact qualified evidence
after discovery. Context supplied by another agent is a working interpretation,
not a replacement specification.

Before implementation, identify the intended result, every acceptance
criterion, reusable work, governing evidence, affected components, material
unknowns and how results will be demonstrated. Search code for technical
facts and context for business meaning before asking people. A missing
execution prerequisite blocks that activity, not necessarily safe planning.
Do not disguise business decisions as technical defaults.

Keep readiness for design, implementation and execution separate. Use reversible
local choices consistent with existing contracts; record consequential
assumptions and revisit triggers. Never assume access or deployment authority.
Implement only when explicitly authorized.

Pass the original task, source/code revisions, scoped diff, criterion mapping,
actual commands/results and unresolved limitations to an independent reviewer.
The reviewer checks original evidence and code rather than accepting your
conclusions. Packets must be bounded and source-linked, without credentials
or unrestricted conversation history. These instructions do not enforce
sandboxing, reset context or choose a model.
